# S-008 – Ochrona brancha main

Epik: E0 – Fundament repo (M0) | Kto: CC+P | Status: todo | Zależy od: S-004

## Cel
Do `main` trafia tylko kod, który przeszedł przez PR z zielonym CI – bez przypadkowych pushy i scaleń z czerwonymi testami.

## Kontekst
Repo `JustVector/daietAplha` na GitHubie. Zasada z CLAUDE.md „nie commituj bezpośrednio na `main`” jest dziś tylko umową – ochrona brancha wymusza ją technicznie. Wymagany check to job CI z S-004 (`lint i testy`).

Ustawienia (reguła rulesetu lub branch protection dla `main`):
- zmiany tylko przez pull request,
- wymagany zielony check CI przed scaleniem, branch aktualny względem `main`,
- zakaz force push i usuwania `main`.

Uwaga: ruleset dla repo prywatnego wymaga płatnego planu GitHub (Pro/Team); dla repo publicznego działa na planie darmowym.

## Kryteria akceptacji
- [ ] Reguła dla `main` włączona zgodnie z „Ustawienia” powyżej
- [ ] Próba `git push` bezpośrednio na `main` zostaje odrzucona
- [ ] PR z czerwonym CI nie da się scalić
- [ ] Konfiguracja opisana w `docs/` (co jest włączone i jak to zmienić)
